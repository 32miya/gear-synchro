How to play

遊び方

  • 歯車をつかんで円を描くようにドラッグすると、1歯ずつカチッと回ります。
  • 回した歯車の隣は、逆向きに同じ歯数だけ連動します。
  • 噛み合った2枚の▲が向き合った状態で指を離すと、2枚とも外れます。
  • 外れたときの衝撃で、隣の歯車が1歯回ります。これで別のペアが向き合うと連鎖します。
  • 相手がいなくなった歯車は、▲を真上の目盛りに合わせると外れます。
  • 手前の層を全部外すと、奥の層が操作できるようになります。
  • 銀の輪がある歯車は奥の歯車と同じ軸です。回すと奥も同じ角度だけ回り、輪の中の小さな▲が奥の歯車の向きを示します。「×2」は奥が倍の歯数の組み合わせです。

ラチェット歯車

  • 「±3」のような札が付いた歯車は、1カチで札の歯数ずつしか回せません（ステージ6から登場）。
  • 止まれる位置は、歯数と刻みの最大公約数で決まります。8歯を3歯刻みで回すと全8か所に止まれますが、12歯を3歯刻みで回すと4か所だけです。
  • 直接回しても届かない向きは、隣の歯車を回して合わせます（隣から回されるときは1歯単位で動きます）。

数字モード

  • 「数字 ON」にすると、歯車の中央に「相手を向くまで、時計回りにあと何歯か」が表示されます。噛み合う相手が複数ある歯車は、中央の周りに相手の方向を指す小さな数字が並びます。札には歯数も出ます。
  • 歯車を時計回りに k 歯回すと、その歯車の数字はすべて k 減り、隣の歯車の数字は k 増えます（どちらも歯数で割った余り）。
  • 噛み合った2つの数字が両方 0 になれば、そのペアが向き合っています。相手のいない歯車は、中央の数字が 0 で12時です。
  • 例：12歯の歯車の数字が 5 のとき、隣を3歯回すと 8 になります。16歯の数字 14 は、2歯戻すのと同じです。
向き合っている 片方だけ向いている 奥と同軸

ステージの進み方

  • チュートリアル：ステージ1は歯車2個・1手（▲を向き合わせる）、ステージ2は3個（逆回転の連動・衝撃・孤立ギア）、ステージ3は2層×2個（同軸と層の切り替え）。回す量も1〜2歯に抑えています。
  • 難易度：ステージ4から通常生成。3ステージごとに層が1つ増え（ステージ7で2層）、ステージ16で5層。手前の層は最大9個、奥ほど1個ずつ少なくなります。

点数の計算

  • 外した歯車：1個 100点 × 連鎖段数（2連鎖目に外れた歯車は1個200点、3連鎖目は300点）
  • 層クリア：500点 × 層の深さ（2層目なら1,000点）
  • ステージクリア：1,000点。目安手数以内ならさらに +1,000点
  • 手数ボーナス：(目安 × 2 − 手数) × 150点。目安の2倍を超えると0点
  • 1手戻す・やり直すと点数も巻き戻ります。解答の再生は加点しません。ベストスコアはこの端末に保存されます。
Design notes

1. クラス構造・データ設計

Gear（歯車データ）

  • id, layer(0〜4), teeth(8/12/16), x, y 配置と歯数。ピッチ半径 = モジュール × 歯数 / 2
  • count:int 噛み合い点を通過した歯の累計（時計回りが正）。唯一の回転状態
  • axle, ratio 同じ軸でつながった1つ奥の歯車と、その歯数倍率（1 または 2）
  • pos = count mod teeth／alive／phase（歯形の描画オフセット）

GearNetwork（接続・連動管理）

  • adj[] 同じ層の中だけの噛み合い隣接リスト（各層は木の集まり）
  • turn(id, d) 歯車を d 歯回し、同軸の奥へ d × ratio 歯を伝える（さらに奥へも伝わる）
  • rotate(id, k) 対象 +k 歯、同じ層の生存隣接に −k 歯。どちらも turn 経由なので同軸に伝わる
  • activeLayer() 生存ギアがある最も手前の層。操作と判定はこの層だけ
  • target(a,b)／findMatches(layer)／remove／shock／resolveAll

StageGenerator（逆算生成）

  • layoutStage(sizes) 層ごとに配置。奥の層は手前の歯車と同じ座標に「軸」を1〜2本立て、そこから木を伸ばす
  • generate(sizes, steps) 手前の層から順に逆算し、最後に全層通しで検証

整数管理と同軸の倍率

噛み合い: Δθ_B = −Δθ_A × N_A / N_B → Δt_B = −Δt_A
同軸　　: Δθ_奥 = Δθ_手前 → Δt_奥 = Δt_手前 × N_奥 / N_手前

1回転を48単位（8・12・16の最小公倍数）とすると、1歯は 6・4・3 単位です。同軸で奥の歯車が歯の途中で止まらないよう、組み合わせを 8→8、8→16、12→12、16→16 に限定しています。倍率は必ず 1 か 2 になり、全歯車の状態を歯数の整数のまま持てます。

2. 逆算生成アルゴリズム（多層版）

generate(sizes[], steps[]):
  repeat:
    layoutStage(sizes)                  // 層ごとに木/森、同軸リンク、接触角は歯ピッチの公倍数
    C ← 各層の木を最大マッチングし、ペアが向き合う count（余りは −1）
    acc ← 0                            // 手前の層の操作で奥へ伝わった回転の累計
    for L in 0..層数-1:
      moves_L ← 層Lのギアを steps[L] 個、各 ±(1..5) 歯
      act_L ← C_L − (moves_L が層L自身に与える線形効果)   // 層Lが現れた瞬間の状態
      層Lだけを act_L から本番ルールで再生（奥は0から開始して伝達量を計測）
        - 現れた瞬間に一致があれば却下
        - 層Lが全消しになる手順 order_L を探す（逆順＋シャッフル）
      start_L ← act_L − acc_L           // 手前の操作で奥が回る分を先に差し引く
      acc += 計測した奥への伝達量
    solution ← order_0 + order_1 + …
    全層を start から本番ルールで通し再生し、全消しなら採用

奥の層は手前を操作するたびに回されるので、最初の盤面ではわざとずれた向きで置かれています。手前を正しく解くと、奥は「現れた瞬間に解ける状態」に近づく仕組みです。

ルール上の決めごと

  • 連動は隣接1段まで。同軸だけは軸を通して奥へ伝わります。
  • 判定は指を離した時。ドラッグ中は向き合ったペアが光るだけです。
  • 衝撃は同じ層の隣接生存ギアに +1 歯。同軸を通して奥にも伝わります。
  • 孤立ギアは12時に合わせると単独で外れます。
  • ラチェット：Gear.step（2〜4）。プレイヤー操作は step 歯単位、噛み合い・同軸・衝撃で回されるときは1歯単位。生成時は step を持つギアの逆回しを step の倍数に限定するので、解は必ず存在します。
  • 数字モード：表示値は (target(a,b) − count) mod N。内部の整数状態をそのまま見せているだけなので、計算で解いた答えと盤面が必ず一致します。

Unity 移植メモ

層は Z 方向に並べ、奥の層ほどスケールと明るさを下げます。transform.localRotation = Quaternion.Euler(0, 0, -visCount * 360f / teeth) で、visCount を count にバネ補間すれば同じラチェット感になります。
